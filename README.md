# СкладПромо — Интернет-магазин

Интернет-магазин промо-товаров с витриной, корзиной, оформлением заказов и административной панелью.

---

## Текущий статус (обновлено 10.09.2026)

**Живой сайт:** [salegifts.ru](https://salegifts.ru), VPS Timeweb, задеплоен на актуальный `master`. Каталог товаров ведётся через админку и меняется независимо от git — актуальное число позиций смотрите в самой админке, а не в этом файле.

Полный список находок и решений — [`docs/Codex/SEO_VISIBILITY_FIX_2026-09-07.md`](docs/Codex/SEO_VISIBILITY_FIX_2026-09-07.md) и история коммитов с префиксом `feat(seo)`/`fix(seo)`.
- **Редизайн витрины «Инвентарный журнал»** (08–09.09.2026) — Концепт 1 по мега-ТЗ [`docs/Codex/REDESIGN_BRIEF_SKLADPROMO_2026-09-08.md`](docs/Codex/REDESIGN_BRIEF_SKLADPROMO_2026-09-08.md), проверен серией прогонов `/design-jury`. Осознанное отступление от ТЗ по решению владельца — акцентный цвет `--brand-accent` и scroll-reveal анимации (раздел 5 ТЗ их запрещал для v1).
- **Доработка каталога на десктопе** (09.09.2026) — выравнивание карточек по нижнему краю, лимит фильтра 5 вместо 6 на группу (чтобы сайдбар помещался без скролла), закреплённая при скролле панель сортировки, пагинация «20 карточек + Показать ещё» вместо полного списка на странице.
- **Ручная сортировка каталога** (09.09.2026) — перетаскивание строк мышью в админке («Товары»); порядок строк в `products.json` и есть порядок показа в каталоге.
- **Вкладка «Компания» и юридический слой** (10.09.2026) — реквизиты, банковские данные, адрес и график склада, GPS. Всё рендерится условно: незаполненное поле нигде не показывается. Реквизиты попадают в футер и в `Organization` JSON-LD.
- **Редизайн каталога, страниц категорий и карточки товара** (10.09.2026) — `/catalog` с матрицей категорий и живым поиском, страницы категорий с гидом покупателя и смежными разделами, карточка товара с селектором количества, липкой панелью покупки, зумом фото по клику и покупкой прямо из блока «Похожие товары».
- **Служебные страницы** (10.09.2026) — [`/delivery`](https://salegifts.ru/delivery) (доставка и оплата) и [`/privacy`](https://salegifts.ru/privacy) (политика обработки ПД). Обе в единой дизайн-системе; политика — обязательное требование 152-ФЗ, вместе с ней в корзине и форме опта появились чекбоксы согласия.
- **Коммерческий слой** (10.09.2026) — оптовая сетка цен на карточке (1–9 / 10–49 −10% / от 50 −20%), блок нанесения логотипа (только для товаров, где услуга включена в админке), B2B-FAQ с ответами из админки, сезонный хаб `/podarki-na-novyj-god` с подборками, которые собираются вручную в карточке товара.
- **Починка Telegram-уведомлений** (10.09.2026) — два заказа сохранились, но уведомления не ушли. Разбор и решение — в разделе «Особенности сервера» ниже; заодно код научился замечать недоставленные уведомления вместо тихого отказа.

Регресс-проверка (`node scripts/verify-seo.js`) проходит на каждый коммит — см. раздел «SEO-проверка перед публикацией».

**Сквозной принцип проекта: не выводить неподтверждённое.** Пустое поле не превращается в заглушку, а факт, которого нет в данных, не появляется в тексте. Поэтому реквизиты, карта склада, условия нанесения логотипа, B2B-FAQ и сезонные подборки рендерятся только при заполненных данных, а страницы `/privacy` и `/podarki-na-novyj-god` при пустых данных отдают 404 и не попадают в sitemap. Это не перестраховка: за время работы над проектом несколько раз приходилось убирать из готовых страниц придуманные сроки отгрузки, несуществующие услуги и вымышленных перевозчиков.

## Дизайн

Витрина оформлена по дизайн-системе в стиле Nike ([`DESIGN-nike.md`](DESIGN-nike.md)): CTA-пилюли, плоские карточки товаров без теней и скруглений (фото на сером фоне), крупный uppercase-заголовок кампании (Bebas Neue) и Inter для интерфейса. Применено к главной и страницам товаров; админ-панель сохраняет свой служебный стиль.

С 09.09.2026 действует редизайн «Концепт 1: Инвентарный журнал» ([`docs/Codex/REDESIGN_BRIEF_SKLADPROMO_2026-09-08.md`](docs/Codex/REDESIGN_BRIEF_SKLADPROMO_2026-09-08.md)) — базовая палитра осталась монохромной, но добавлен акцентный синий `--brand-accent: #1151ff` (цена, активные фильтры и сортировка, ховеры) и scroll-reveal анимация появления карточек. Оба — осознанное отступление от ТЗ по прямому решению владельца сайта; сам ТЗ по умолчанию запрещал акцент и анимации в первой версии.

## Возможности витрины

- Каталог товаров (состав и число позиций — в админке) с фильтрами по категории, материалу и цвету (чекбоксы, OR внутри группы, AND между группами)
- Счётчики значений в фильтрах; группы с более чем 5 вариантами сворачиваются («Показать ещё»)
- Иконки SVG у каждого значения фильтра; цветовые точки у фильтра по цвету
- Сортировка по цене и количеству, панель сортировки закреплена при скролле каталога (десктоп)
- Поиск по названию и артикулу
- Каталог на главной подгружается по 20 карточек — «Показать ещё» открывает следующие 20, пока список не закончится
- Цена в карточке и на странице товара — **ровно та, что указана в админке** (поле «Цена, ₽»), без наценки. Кнопка «Запросить оптовые условия» на странице товара — лид уходит в админку (вкладка «Заявки на опт») и в подключённый Telegram-бот
- Страница каждого товара с ЧПУ-адресом (`/product/:slug`) — server-side rendering для поисковиков
- Корзина (localStorage), оформление заказа, форма с именем и телефоном. Поле телефона — маска `+7XXXXXXXXXX`: только цифры, автоформатирование при вводе, валидация на клиенте и сервере (та же маска — на форме заказа и на форме «Запросить оптовые условия»)
- **Согласие на обработку ПД (152-ФЗ)** — чекбокс в корзине и в форме опта. Не отмечен по умолчанию: предзаполненная галочка согласием не считается. Без отметки запрос на сервер не уходит вообще
- **Страница товара:** селектор количества, липкая панель покупки на мобильном, зум фото по клику в модальном окне, покупка прямо из блока «Похожие товары»
- **Оптовая сетка цен** на карточке: 1–9 шт. — розница, 10–49 шт. — −10%, от 50 шт. — −20%. В `Offer`, JSON-LD и товарные фиды при этом уходит только розничная цена за штуку, иначе у товара оказалось бы несколько разных цен
- **Нанесение логотипа** — блок появляется только у товаров, где услуга включена в админке, и показывает только заполненные поля (способы, срок, минимальный тираж)
- **Блок «Вопросы о товаре»** — товарные вопросы (наличие, характеристики) плюс коммерческие: оплата юрлицом, резерв, ЭДО, документы, образцы, приёмка. Ответы редактируются в админке
- **`/catalog`** — матрица категорий, живой поиск по каталогу, добавление в корзину прямо из плитки
- **`/delivery`** и **`/privacy`** — служебные страницы; на `/delivery` есть кнопка копирования реквизитов для оплаты юрлицами и карта склада (при заполненных GPS-координатах)
- **`/podarki-na-novyj-god`** — сезонный хаб с подборками «Премиум-подарки», «Универсальные бизнес-сувениры», «Наборы для праздника». Товары в подборки отмечает менеджер в админке

## Возможности админки

- **Заказы:** список, статусы (новый / в работе / выполнен), модалка с деталями заказа
- **Заявки на опт:** лиды с кнопки «Запросить оптовые условия» на странице товара — товар, имя, контакт, комментарий; статусы (новая / обработана), удаление; при поступлении новой заявки — уведомление в Telegram
- **Товары:** инлайн-редактирование цены, кол-ва, видимости; загрузка фото/видео и отдельного фото для товарных фидов (обложка/инфографика — заменяет обычное фото только в `/feeds/google.xml` и `/feeds/yandex.yml`)
- **Товары:** модалка редактирования — **артикул** (переименование, с проверкой уникальности), фото, название, описание, категория, материал, цвет, **SEO-заголовок и мета-описание**
- **Товары:** создание нового товара («+ Новый товар» — создаёт пустую карточку со сгенерированным артикулом и сразу открывает её на редактирование)
- **Товары:** копирование товара (новый артикул `<артикул>-copy`, фото/видео копируются)
- **Товары:** удаление товара (с подтверждением)
- **Товары:** чекбоксы + «выбрать все», массовое сохранение и массовое удаление
- **Товары:** ручная сортировка — перетаскивание строки за ⠿ меняет порядок показа в каталоге и на главной (сохраняется сразу, без кнопки «Сохранить»; недоступно при активном поиске по таблице)
- **Товары:** подборка сезонного хаба — выпадающий список в карточке товара («Премиум-подарки» / «Универсальные бизнес-сувениры» / «Наборы для праздника» / не участвует)
- **Товары:** нанесение логотипа — галочка «услуга доступна», способы нанесения, срок изготовления, минимальный тираж. Пока галочка выключена, сайт про нанесение не пишет ничего; способ **не** подставляется автоматически по материалу товара
- **Контакты:** редактирование hero-баннера (заголовок и подзаголовок), контактных данных и ссылок на соцсети
- **Компания:** юрлицо (наименование, ИНН, КПП, ОГРН, адрес), банковские реквизиты, склад (город, адрес, GPS, дни и часы работы, условия самовывоза), фотографии склада. Заполнение GPS автоматически включает интерактивную карту Яндекса на `/delivery` и на главной — без правок кода и без деплоя
- **B2B-условия:** ответы для блока «Вопросы о товаре» — оплата юрлицом, срок резерва, системы ЭДО, закрывающие документы, образцы, приёмка. Незаполненное поле не даёт вопроса с пустым ответом, вопрос просто не показывается
- **Фиды:** ссылки на товарные фиды и карту сайта (открыть / скопировать для подачи в Merchant Center и Яндекс.Вебмастер) и кнопка «Проверить фиды» — подтверждает, что правки в товарах попали в фид (число товаров + время проверки)
- **Уведомления:** настройка email (Gmail SMTP) и Telegram-бота для оповещений о заказах

## SEO и AI-оптимизация страниц товаров

Каждый товар имеет собственную страницу с человекочитаемым ЧПУ-адресом
(`/product/транслит-названия-АРТИКУЛ`, напр. `/product/avtoruchka-v-futlyare-krasnoe-derevo-140812`), которую рендерит сервер:

- **ЧПУ-адрес** с транслитерацией названия; старые ссылки `/product/АРТИКУЛ` отдают **301-редирект** на актуальный ЧПУ (сохраняется индекс и ссылочный вес)
- `<title>` — из поля `meta_title` (импортировано для каждого SKU, см. «Первичный импорт данных»), либо автогенерация `{название} — купить | СкладПромо`, если поле не задано
- `<meta name="description">` — рендерится из шаблона `meta_description_template` с ценой и остатком, подставленными в момент показа страницы (а не сохранённым снимком — снимок устаревал при первом же изменении цены). Регион не упоминается: город магазина не публиковался ни на одном этапе, «купить в СПб/Санкт-Петербурге» в текстах — намеренно исключённый паттерн, `scripts/verify-seo.js` проверяет его отсутствие
- Open Graph теги (`og:title`, `og:description`, `og:image`, `og:url`), `<link rel="canonical">` (на ЧПУ)
- JSON-LD: **Product** + **Offer** (цена, наличие, артикул, категория, изображение), **BreadcrumbList** и **FAQPage**
- **Про FAQPage.** Разметку однажды снимали как устаревшую — Google убрал FAQ-сниппет из выдачи 07.05.2026. Вернули: Яндекс и AI-ответы её по-прежнему читают. Условие из [`docs/product-card-template-tz.md`](docs/product-card-template-tz.md) — «добавлять только когда вопросы и ответы полностью видимы на странице и не являются рекламными обещаниями» — теперь не на честном слове: `verify-seo.js` проверяет, что каждый вопрос и ответ из разметки присутствует в видимом HTML. Разметка, обещающая поисковику то, чего нет на странице, роняет тест
- Microdata `itemprop` прямо в HTML
- Поля `meta_title` / `meta_description` (кастомные) редактируются в модалке товара в админке и перекрывают авто-генерацию
- **`/sitemap.xml`** (главная + все товары в наличии), **`/robots.txt`**, **`/llms.txt`** (обзор каталога с ценами и наличием для AI-краулеров и ответных нейросетей)
- **Товарные фиды** для загрузки в кабинеты вебмастеров:
  - **`/feeds/google.xml`** — Google Merchant Center / Google Shopping (RSS 2.0, namespace `g:`)
  - **`/feeds/yandex.yml`** — Яндекс.Вебмастер «Товары и цены» / Яндекс.Маркет (YML, `yml_catalog`)
  - Оба фида генерируются из каталога (цена, наличие, ЧПУ-ссылки, изображения) и всегда актуальны; ссылки на них указываются в кабинетах один раз. On-page разметку JSON-LD **Product/Offer/BreadcrumbList** Google Search Console считывает со страниц автоматически.
  - Все ссылки в фидах (товар, изображение) строятся от **домена, с которого фид фактически запросили** (`req.get('host')`), а не от фиксированного `SITE_URL` — так фид сразу рабочий и через технический домен хостинга, и через основной домен, без переключения в коде.
  - Для каждого товара можно загрузить **отдельное фото для фида** (обложка/инфографика) в админке — вкладка «Товары» → колонка «Медиа» → «🖼️ Фото для фида». Если оно загружено, фиды используют именно его вместо обычного фото товара; на странице товара по-прежнему показывается обычное фото.

## Первичный импорт данных

Товары и фотографии уже включены в репозиторий (`server/data/products.json`, `public/images/`).

Если нужно перегенерировать из исходных файлов (`Контент/`):

```bash
pip install -r scripts/requirements.txt
python scripts/import_data.py
```

Скрипт читает `Склад_2019_Sale_Опт.xls` и извлекает фотографии из `Технологика_распродажа.pdf`.

## Деплой

> **Railway всё ещё присылает письма о падении сборки — это ожидаемо и на сайт
> не влияет.** В репозитории от Railway не осталось ничего (`railway.toml`
> удалён, GitHub Actions нет), но сам проект в Railway остался подписан на
> GitHub-репозиторий и на каждый push в `master` пытается собраться и падает.
> Лечится только в панели Railway: удалить проект или отвязать репозиторий
> (Settings → Source → Disconnect). Из кода это не отключается.

**Сайт больше не на Railway.** Railway использовался до 27.08.2026; с этой даты
salegifts.ru работает на собственном VPS Timeweb (Docker Compose, nginx общий с
соседним проектом `avtoservice` на том же сервере). Оставшийся в репозитории
`railway.toml` был мёртвым файлом с самого первого коммита и не отражал
реальный деплой — удалён; если он всплывёт в истории или в старой ветке,
это не инструкция к действию.

Текущая схема:

- **Сервер:** VPS Timeweb, Docker Compose. Каталог `/opt/sklad` **не является
  git-репозиторием** — код туда попадает архивом (`git archive HEAD`), не
  через `git pull`.
- **nginx общий с соседним проектом.** vhost для salegifts.ru лежит в
  `/opt/nginx-vhosts/salegifts.conf`, живёт в контейнере `avtoservice-nginx-1`
  из соседнего compose-проекта. Порты 80/443 занимает только он. Любое
  изменение `deploy/nginx-salegifts.conf` перед `reload` обязано пройти
  `docker exec avtoservice-nginx-1 nginx -t` — битый конфиг положит и соседний
  сайт тоже.
- **Данные — в именованном Docker-томе** `sklad-data`, смонтированном в
  `/data` (см. `docker-compose.yml`). Пересборка образа его не трогает; см.
  «Персистентность данных» ниже.
- **Порядок выкатки:** `git archive` → `scp` архива на сервер → распаковка
  поверх `/opt/sklad` → (если менялся nginx-конфиг) `nginx -t` до reload →
  `docker compose up -d --build` → `docker exec avtoservice-nginx-1 nginx -s
  reload`.
- Shell-скрипты в архиве обязаны быть в LF (`.gitattributes` это закрепляет:
  `*.sh text eol=lf`) — CRLF в shebang `docker-entrypoint.sh` делает
  интерпретатором несуществующий `/bin/sh\r`, и контейнер уходит в цикл
  перезапуска.

> **Важно:** токены сессии AdminPanel хранятся в памяти сервера и сбрасываются
> при каждом деплое/перезапуске. После деплоя нужно войти заново.

### Особенности сервера (важно прочитать до диагностики сети)

Три вещи, каждая из которых уже съедала часы на разбор.

**1. Telegram доступен только по одному IP, и его нельзя получить через DNS.**
DNS отдаёт для `api.telegram.org` единственный адрес `149.154.166.110` — с
этого сервера он не отвечает, TCP 443 уходит в таймаут (провайдерская
блокировка). Рабочий адрес того же API — `149.154.167.220`; он закреплён в
`docker-compose.yml` через `extra_hosts`. Подменяется только резолв имени: SNI
и проверка сертификата остаются для `api.telegram.org`, TLS не страдает.
Если уведомления снова замолчат — сначала проверьте, отвечает ли этот адрес:

```bash
docker exec sklad-app-1 node -e "fetch('https://api.telegram.org').then(r=>console.log(r.status)).catch(e=>console.log(e.cause?.code))"
```

**2. Выдавать контейнеру IPv6 — тупик, не тратьте на это время.** По IPv6
Telegram доступен, и идея кажется правильной, но: сеть `avtoservice_default`
принадлежит compose соседнего проекта (включение в ней IPv6 требует
пересоздания сети и остановит соседний сайт), у хоста нет IPv6-подсети —
только один адрес `/128`, а включение `net.ipv6.conf.all.forwarding=1`
**роняет IPv6 у самого хоста** (проверено 10.09.2026, откатывали).

**3. `accept_ra` на eth0 обязан быть `2`.** Закреплено в
`/etc/sysctl.d/99-ipv6-ra.conf`. При значении `0` (как было до 10.09.2026)
хост принимает RA-маршрут по умолчанию, но не обновляет его — маршрут
догорает и IPv6 отваливается примерно раз в полчаса, а потом случайно
восстанавливается. Именно это «мигание» сбивает диагностику: связь то есть,
то нет. Форвардинг в этот файл добавлять **нельзя** — см. пункт 2.

**Лимит Docker Hub.** Образ тянется анонимно, и при большом числе выкаток за
день сборка падает с `429 Too Many Requests`. Сайт при этом не страдает:
неудачная сборка не трогает работающий контейнер. Если правка касается только
`docker-compose.yml` (а не кода), контейнер можно пересоздать без сборки:
`cd /opt/sklad && docker compose up -d --no-build`.

### SEO-проверка перед публикацией

- `SITE_URL` в `.env` на сервере должен содержать конечный основной
  HTTPS-домен (`https://salegifts.ru`) — canonical, sitemap и товарные фиды
  строятся от него.
- SEO-метаданные 69 SKU находятся в docs/product-meta-tags.csv; импорт
  выполняется скриптом node scripts/import-product-meta.js.
- Проверка server-rendered карточек, категорий, sitemap и robots:
  `node scripts/verify-seo.js` (локально — против `preview_start` на порту
  3000/3101; на проде — `SEO_TEST_BASE=https://salegifts.ru node
  scripts/verify-seo.js`). Локальный `server/data/products.json` может
  отставать от боевых цен/остатков/видимости, которые правятся через
  админку независимо от git — при расхождении верить проду, а не локальному
  файлу.
- `/sale/` появляется только при товарах с заполненными старой и новой ценой,
  размером скидки и условиями/сроком акции.

## Persistent data (Docker volume, not Railway)

In production the app runs under Docker Compose with a named volume,
`sklad-data`, mounted at `/data` (`DATA_DIR=/data`, set in the server's
`.env`) — see `docker-compose.yml`. `docker-entrypoint.sh` seeds an empty
volume once from `server/data`, copying each `*.json` file only if it doesn't
already exist at the destination; contacts, products, orders, company details
and B2B answers saved through the admin panel are never overwritten by a
redeploy, because the image's copy of `server/data` is irrelevant once the
volume already has its own file.

**Практическое следствие, на которое уже наступали:** правка seed-файла в
git **не** доедет до прода, если этот файл в томе уже есть. Так GPS-координаты
склада, добавленные в `server/data/company.json`, не появились на сайте после
деплоя — файл в томе существовал с первого запуска. Новый файл (например,
`b2b.json`) переносится нормально, потому что в томе его ещё нет. Менять
живые данные нужно через админку, а не коммитом в seed.

The same volume also stores files uploaded through the admin panel:
`${DATA_DIR}/uploads/images` and `${DATA_DIR}/uploads/media`. On first boot
each is seeded once from `public/images` / `public/media` (the git-tracked
seed photos), then anything uploaded afterwards is served from the volume
with priority over the seed files, so it survives redeploys — including the
images referenced by the Google Merchant (`/feeds/google.xml`,
`<g:image_link>`) and Яндекс.Вебмастер (`/feeds/yandex.yml`, `<picture>`)
feeds.

This is unrelated to Railway — there is no Railway Volume in the current
setup. If you see "Railway Volume" in an old comment or commit message, it
describes the pre-27.08.2026 hosting and does not apply anymore.
