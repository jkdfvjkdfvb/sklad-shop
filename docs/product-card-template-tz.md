# ТЗ: массовый SEO/AEO-шаблон товарной карточки «СкладПромо»

## Результат и границы

Цель — получать органический трафик по точным товарным запросам на карточки и сделать каждую карточку пригодной для прямого цитирования поиском и AI-ответами. Вершина воронки не должна размывать товарные страницы:

| Уровень | Семантика | Пример |
| --- | --- | --- |
| Главная | общая сувенирная продукция, бизнес- и корпоративные подарки, промо-товары, опт | «сувенирная продукция», «корпоративные подарки», «бизнес подарки» |
| Категория | тип товара с коммерческим модификатором | «брелок для ключей купить», «настольные часы купить» |
| Карточка | точная модель + тип + фактические характеристики | «ручка в футляре из красного дерева», «брелок фонарик», «дорожный будильник» |
| `/sale/` | распродажа и уценённые остатки | «распродажа сувениров» |
| `/uslugi/nanesenie-logotipa/` | брендирование | «сувениры с логотипом» — только после запуска партнёрской услуги |

Не добавлять в `Title`, H1 или основной текст всех товарных карточек «корпоративные подарки», «мерч», «сувенирная продукция», «изготовление» и «с логотипом». Они не описывают конкретный SKU и должны продвигаться на верхних уровнях.

Текущие рекомендуемые значения для 69 SKU находятся в [product-meta-tags.csv](product-meta-tags.csv), а первичный Wordstat-кластер — в [semantic-demand.csv](semantic-demand.csv).

## Выявленные исправления в текущем шаблоне

Проверенная карточка `/product/avtoruchka-v-futlyare-krasnoe-derevo-140812` уже выдаёт основной контент в HTML — это сохраняем. Обязательно исправить:

1. Убрать искусственный регион «в СПб» из Title и description: целевой регион — вся Россия. Региональные посадочные допустимы только при реальной локальной инфраструктуре.
2. Не обрезать название товара многоточием в `title` и OG Title.
3. Перевести `canonical`, `og:url`, `og:image` и `Offer.url` на единый конечный HTTPS-домен. Railway-домен — временный: до переезда не должен становиться каноническим доменом в индексе.
4. Заменить плейсхолдеры телефона и социальных сетей на реальные реквизиты до массовой индексации.
5. Не называть магазин брендом товара в Product JSON-LD. Поле `brand` выводить только при наличии реального бренда или производителя SKU.

## Обязательные данные SKU

Добавить к каждому товару следующие поля. SEO-генератор не должен придумывать значения, если поле пустое.

```text
id, slug, seo_name, short_name, article, category_slug, category_name
material, color, dimensions_mm, weight_g, package_contents, compatibility
retail_price, wholesale_price_from, stock_qty, stock_updated_at
image_urls[], video_url, manufacturer_or_brand
is_sale, old_price, discount_percent, sale_start_at, sale_end_at, sale_terms
logo_service_available, logo_service_fulfilled_by_partner, logo_service_min_qty,
logo_service_lead_time, logo_service_methods[]
```

`seo_name` — нормализованное название для H1 и мета-тегов; оно не содержит технических сокращений вроде «д/», лишних пробелов и опечаток. Исходное складское наименование сохраняется отдельно.

## Правила генерации мета-тегов

### H1

```text
{seo_name}
```

Один H1 на странице. Он полностью совпадает с видимым названием и `Product.name` в JSON-LD.

### Title

```text
{short_name или seo_name} — купить | СкладПромо
```

Допустимо добавить один подтверждённый дифференциатор, если итог не длиннее 60–65 видимых символов: «металлический», «на 4 порта», «дорожный», «в футляре». Слово «купить» ставится в каждом Title ровно один раз.

Не добавлять в Title: город, «доставка по России», «оптом», «распродажа», «скидка», «акция», «нанесение логотипа» — кроме специальных посадочных, для которых это главная тема.

### Description

```text
{seo_name}. Арт. {article}. В наличии на складе: {stock_qty} шт.
Цена {retail_price} ₽. Опт — по запросу.
```

Ограничение — до 160–170 символов. Цена и остаток должны подставляться при серверном рендеринге из того же источника, что и видимый блок цены. При `stock_qty = 0` фраза меняется на «Нет в наличии»; не оставлять устаревшее «В наличии» в мета-описании.

### Распродажа и скидка

Слова «распродажа», «скидка», «акция», «ликвидация остатков» разрешены только если одновременно заполнены `is_sale = true`, старая цена, новая цена, размер выгоды и сроки или условия акции. На всех остальных SKU они не подставляются. Это сохраняет доверие в сниппете и соответствует фактической цене.

### Нанесение логотипа через партнёра

Не писать «с логотипом», «изготовление» или «нанесение» в карточечных `Title` по умолчанию. После документированного запуска партнёрской услуги допустим дополнительный блок:

> Нанесение логотипа возможно по запросу через партнёрское производство. Укажите модель, тираж и срок — менеджер рассчитает стоимость и сроки.

Он выводится только при `logo_service_available = true` и наличии минимального тиража, сроков, способа передачи макета, партнёрского SLA и ответственного менеджера. Нельзя заявлять собственное производство, бесплатный макет, конкретные сроки или виды нанесения без подтверждения.

## Обязательная структура страницы

```text
BreadcrumbList: Главная → Каталог → {категория} → {H1}
H1
Галерея: минимум 3 фото при наличии, видео при наличии
Цена + старая цена и выгода только для активной акции
Статус остатка и дата его обновления
Кнопки: «В корзину», «Запросить оптовые условия»
Короткий факт-блок (3–5 фактов)
Таблица характеристик
Описание: 250–500 полезных слов, если есть исходные данные
«Что в комплекте» / совместимость / ограничения
Блок партнёрского нанесения — по условиям выше
FAQ из 3–5 вопросов
Похожие товары из той же категории
```

### Факт-блок для AI-ответов

Перед развёрнутым описанием вывести статичный, видимый в HTML блок:

```html
<section aria-labelledby="facts-heading">
  <h2 id="facts-heading">Коротко о товаре</h2>
  <dl>
    <dt>Артикул</dt><dd>{article}</dd>
    <dt>Материал</dt><dd>{material}</dd>
    <dt>Цвет</dt><dd>{color}</dd>
    <dt>Наличие</dt><dd>На складе: {stock_qty} шт. (обновлено {stock_updated_at})</dd>
  </dl>
</section>
```

Показывать только фактически заполненные параметры. Не писать «идеально для корпоративного подарка», «премиальный», «экологичный», «долговечный», если это не доказано характеристикой или документом.

### FAQ

FAQ должен отвечать на товарные вопросы, а не повторять ключевые слова. Минимальный набор:

1. «Есть ли {название} в наличии?» — выводит актуальный остаток.
2. «Какие характеристики у {название}?» — использует только карточку характеристик.
3. «Можно ли купить оптом?» — «Да, оставьте заявку: менеджер подтвердит цену и условия».
4. «Можно ли заказать нанесение логотипа?» — только при активном партнёрском сервисе.

FAQPage JSON-LD добавлять только когда эти вопросы и ответы полностью видимы на странице и не являются рекламными обещаниями.

## Structured data и социальные сети

В initial HTML отдать один согласованный `Product` JSON-LD:

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "{seo_name}",
  "sku": "{article}",
  "image": ["{absolute_https_image_url}"],
  "description": "{plain_short_description}",
  "category": "{category_name}",
  "offers": {
    "@type": "Offer",
    "url": "{canonical_https_url}",
    "priceCurrency": "RUB",
    "price": "{retail_price}",
    "availability": "https://schema.org/{InStock|OutOfStock}",
    "itemCondition": "https://schema.org/NewCondition"
  }
}
```

`priceValidUntil`, `shippingDetails`, `hasMerchantReturnPolicy`, рейтинг и отзывы можно добавлять только при наличии их реальных источников. Не создавать фальшивые отзывы или рейтинг. `og:title`, `og:description`, `og:url`, `og:image`, `twitter:card=summary_large_image` должны совпадать с канонической версией страницы и использовать HTTPS.

## Страницы, которые нужно создать до масштабирования карточек

1. Главная с H1 «Сувенирная продукция и бизнес-подарки со склада» и Title «Сувениры и бизнес-подарки со склада — оптом, в наличии | СкладПромо».
2. SEO-категории: брелоки, часы и будильники, визитницы, папки, портфели, открывалки, наборы для вина, USB-хабы, дорожные товары, офисные аксессуары. Они должны быть полноценными URL, а не только фронтенд-фильтрами.
3. `/sale/`: только товары с документированной скидкой, старой/новой ценой, условиями и датой окончания. H1 «Распродажа товаров со склада».
4. `/uslugi/nanesenie-logotipa/`: запускать после подтверждения подрядчика. Описать процесс, минимальный тираж, реальные сроки, методы, контроль качества и ответственность СкладПромо. Карточки должны ссылаться на неё CTA, но не конкурировать с ней по мета-тегам.

## Техническая индексация

- В каждом ответе 200 должен быть полный title, description, canonical, H1, цена, остаток и JSON-LD без ожидания JavaScript.
- Сгенерировать `sitemap.xml` с главной, категориями, карточками, `/sale/` и активными сервисными страницами. `lastmod` меняется при изменении цены, остатка или контента.
- В `robots.txt` открыть публичные URL для поисковых ботов и дать ссылку на sitemap. Закрыть корзину, API, поиск с параметрами и технические страницы.
- Настроить 301 со старых slug при переименовании. Временно отсутствующий товар оставлять 200 с честным `OutOfStock` и аналогами; снятый навсегда без замены — 410 либо 301 на ближайшую релевантную категорию.
- Не допускать 200-страниц без товара, дублей по `?sort`, `?filter` и HTTP/HTTPS. У каждой карточки один self-canonical на HTTPS.
- Добавить Organization/OnlineStore JSON-LD на главную только с подтверждёнными названием юрлица, телефоном, адресом, email, графиком, политикой доставки и возврата.

## Критерии приёмки

1. Все 69 SKU импортированы из `product-meta-tags.csv`; URL уникальны, Title и Description непустые.
2. В исходном HTML каждого SKU есть H1, Title, description, canonical HTTPS, OG-теги, цена, остаток и валидный Product JSON-LD.
3. Проверка Rich Results не показывает критических ошибок Offer/Product.
4. Во всех карточках Title соответствует точному товарному кластеру; общие сувенирные запросы не вставлены в них автоматически.
5. «Распродажа/скидка/акция» не выводятся без записанных условий скидки.
6. «Нанесение логотипа» не обещается без активного партнёрского процесса.
7. На тестовой выборке из 10 SKU вручную совпадают видимые цена и остаток, мета description и JSON-LD.
