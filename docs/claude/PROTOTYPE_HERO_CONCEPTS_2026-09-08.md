# Прототип: сравнение двух hero-концептов

Статус: throwaway-прототип для сравнения, не production.
Дата: 2026-09-08
Источник: [мега-ТЗ](../Codex/REDESIGN_BRIEF_SKLADPROMO_2026-09-08.md), раздел 11 (два варианта прототипа), раздел 14 (гейт — прототип запущен после подтверждения ТЗ владельцем).

## Файл

`public/prototype-hero-redesign.html` — один статический HTML-файл, отдаётся Express как обычная статика (роут не регистрировался, ничего в `server/` не менялось).

Открыть на локальном dev-сервере:

```
http://localhost:3000/prototype-hero-redesign.html
```

Переключение концептов: `?variant=1` / `?variant=2`, либо плавающая панель внизу экрана (стрелки, клавиши ← →).

## Что сравнивается

Первый экран (hero) в двух композициях из раздела 11 ТЗ, на одном и том же наборе из 12 реальных товаров (получены через `GET /api/products`, отфильтрованы по конкретным артикулам — портфель, глобус, метеостанция, бинокль и т.д. — чтобы состав был одинаковым и не влиял на оценку):

- **Концепт 1 «Инвентарный журнал»** — спокойный заголовок слева, справа строгая контактная сетка 4/3/2 колонки (desktop/tablet/mobile) с подписями «Арт. … / цена».
- **Концепт 2 «Полка крупным планом»** — почти full-bleed мозаика товаров (часть плиток крупнее — эффект витрины), поверх — компактный светлый информационный блок со смещением к нижнему левому углу; на mobile блок уходит под мозаику как обычная секция.

Всё остальное (шапка, блок категорий под hero) — общий контекст, одинаковый в обоих вариантах, не является предметом оценки.

## Что реальное, а что нет

- Фото, артикулы, цены — реальные данные из `server/data/products.json` (через публичный API, без выдумывания цен/остатков).
- Заголовки, подводка и CTA — черновой копирайт для прототипа, финальный текст не утверждён.
- Шапка (поиск/корзина) — заглушка для контекста, не финальный дизайн навигации.

## Проверено

- Desktop (1440px), tablet (~900px), mobile (375px) — оба концепта.
- В процессе сборки исправлены два реальных бага компоновки: переполнение hero-заголовка Bebas Neue из-за слишком узкого `max-width` в ch, и наложение info-island поверх шапки в Концепте 2 из-за недостаточной высоты мозаики под контентом оверлея.
